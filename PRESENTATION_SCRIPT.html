How JDBC Database Connectivity Works

Core Concept

JDBC (Java Database Connectivity) is a Java API that lets Java code talk to any relational database using a standard set of classes and interfaces. You never write socket code — JDBC handles it. You only need 3 things: a driver JAR, a connection URL, and SQL statements.

  • 1
    Load the Driver — The MySQL JDBC driver (mysql-connector-j-8.4.0.jar) is a JAR file that knows how to speak MySQL's binary wire protocol. You load it with Class.forName(). This is a one-time step when the server starts.
  • 2
    Get a Connection — DriverManager.getConnection(URL, user, pass) opens a TCP socket to MySQL, authenticates, and returns a Connection object. Every query needs one.
  • 3
    Create a Statement — Use PreparedStatement for queries with parameters (prevents SQL injection). Use Statement for static queries.
  • 4
    Execute SQL — executeQuery() for SELECT (returns a ResultSet). executeUpdate() for INSERT / UPDATE / DELETE (returns rows affected).
  • 5
    Read the ResultSet — Loop with rs.next(), read columns with rs.getString("col"), rs.getInt("col"), etc.
  • 6
    Close Everything — Use try-with-resources (try (Connection conn = ...)) so connections auto-close and don't leak.
The JDBC connection — this is the bridge between Java and MySQL DBConnection.java 
public class DBConnection {

    // JDBC URL format: jdbc:mysql://<host>:<port>/<database>
    private static final String DB_URL  = "jdbc:mysql://localhost:3306/parksmart?serverTimezone=UTC";
    private static final String DB_USER = "root";
    private static final String DB_PASS = "cseBtech4202";

    static {
        // Step 1 — Load the MySQL JDBC driver into the JVM
        Class.forName("com.mysql.cj.jdbc.Driver");
    }

    // Step 2 — Open a fresh connection for every query
    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(DB_URL, DB_USER, DB_PASS);
    }
}
A complete JDBC query cycle — login example UserDAO.java 
public User login(String email, String password) throws SQLException {

    String sql = "SELECT id, name, email, phone FROM users WHERE email = ? AND password = ?";
                    // ^ the ? marks are placeholders — filled safely by PreparedStatement

    // try-with-resources: conn, ps, rs all auto-close when the block ends
    try (Connection      conn = DBConnection.getConnection();   // Step 2
         PreparedStatement ps   = conn.prepareStatement(sql)) { // Step 3

        ps.setString(1, email);    // bind 1st ?
        ps.setString(2, password); // bind 2nd ?

        try (ResultSet rs = ps.executeQuery()) {  // Step 4 — run SELECT
            if (rs.next()) {                       // Step 5 — read result
                User u  = new User();
                u.id    = rs.getInt("id");
                u.name  = rs.getString("name");
                u.email = rs.getString("email");
                return u;
            }
        }
    }                              // Step 6 — auto-closed here
    return null;
}

try {
    // 1. Mark booking as Completed

DDL — How the Tables Are Structured

Schema
Four tables with primary keys, foreign keys, ENUMs, and constraints database/schema.sql 
-- Table 1: users (stores login accounts)
CREATE TABLE users (
    id       INT AUTO_INCREMENT PRIMARY KEY,
    name     VARCHAR(100) NOT NULL,
    email    VARCHAR(100) NOT NULL UNIQUE,     -- no duplicate emails
    phone    VARCHAR(15),
    password VARCHAR(100) NOT NULL
);

-- Table 2: parking_slots (the physical parking spaces)
CREATE TABLE parking_slots (
    id     INT AUTO_INCREMENT PRIMARY KEY,
    floor  INT                           NOT NULL,
    type   ENUM('Car','Bike')            NOT NULL, -- only these 2 values allowed
    status ENUM('Available','Occupied')   NOT NULL DEFAULT 'Available'
);

-- Table 3: bookings (who parked where and when)
CREATE TABLE bookings (
    id           INT AUTO_INCREMENT PRIMARY KEY,
    user_id      INT,
    vehicle      VARCHAR(20)              NOT NULL,
    vehicle_type ENUM('Car','Bike')        NOT NULL,
    slot_id      INT,
    entry_time   DATETIME                 DEFAULT CURRENT_TIMESTAMP,
    exit_time    DATETIME                 NULL,       -- NULL = still parked
    total_fee    DECIMAL(10,2)            DEFAULT 0,
    status       ENUM('Active','Completed') DEFAULT 'Active',
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL,
    FOREIGN KEY (slot_id) REFERENCES parking_slots(id) ON DELETE SET NULL
);

-- Table 4: payments (billing record for each booking)
CREATE TABLE payments (
    id           INT AUTO_INCREMENT PRIMARY KEY,
    booking_id   INT,
    amount       DECIMAL(10,2)          DEFAULT 0,
    payment_date DATETIME               DEFAULT CURRENT_TIMESTAMP,
    status       ENUM('Pending','Paid')  DEFAULT 'Pending',
    FOREIGN KEY (booking_id) REFERENCES bookings(id) ON DELETE CASCADE
);

"Sir, I have used ENUM for fields like status and type to enforce data integrity at the database level — MySQL will reject any value other than what's defined. Foreign keys ensure referential integrity — a booking cannot reference a user or slot that doesn't exist."
